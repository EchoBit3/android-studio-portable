# ¿Cómo sabemos que el proyecto cumple (y qué no cubrimos)?

> Esta sección es el "chequeo integral": se recorre cada pieza del sistema cubriendo **todo**, incluidos los caminos de error y los casos hostiles. No se toma la recompensa fácil (que "la suite pase"); se fuerza cada rama de decisión y se anota la evidencia.

## Cómo leer este documento

Cada verificación tiene un **ID**, el **método** (suite de `tests/`, comando manual o inspección), y el **criterio** de aprobación. Los IDs se agrupan por atributo de calidad según ISO/IEC 25010: funcionalidad, fiabilidad, seguridad, eficiencia y mantenibilidad (ver `07-estandares.md`).

Leyenda de estados: ✅ PASS verificado en esta sesión · ⚠️ PARCIAL/cubierto en forma manual sobre la instalación real · 🔲 NO CUBIERTO (hueco declarado, se anota para cerrar).

## Huecos declarados (transparencia, no fachada)

- 🔲 **D6 hardware mínimo**: se validó en equipo real de 16 GiB/KVM (ver `03-entorno.md`); el requisito de 8 GiB es extrapolación de la doc oficial, no medido acá.
- 🔲 **F8 en vivo**: la resolución `stable_url` contra la página real de Google se validó una vez en el entorno del operador; el CI no sale a internet a propósito (la suite es hermética y reproducible). La concordancia se re-verifica con el bot de humo periódico (fuera del repo).
- 🔲 **E1 mirror**: la descarga usa los servidores de Google directamente; no se probó fallback a espejo ni reintento de red en la descarga del tar (~1.5 GB).
- 🔲 **S7 explicación de ecosistema**: Dependabot solo aplica a `github-actions` porque el repo es bash puro (sin manifiestos de paquetes). Si en el futuro hubiera `npm`/`pip`, se agrega su ecosistema al mismo archivo.

## Procedimiento para cerrar un hueco

1. Escribir el test que falla (o el comando de verificación) en la suite adecuada.
2. Correr `bash tests/run-tests.sh` → el nuevo test debe quedar verde y el resto intacto.
3. Actualizar este documento (ID → PASS) y `02-pruebas.md` (conteo).
4. Commit semántico y actualización del `CHANGELOG.md` vía la política de versionado (`VERSION`).
